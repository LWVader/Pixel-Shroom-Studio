Cloudflare CSP and Vault recovery form fix

Replace the included files, then run:
npm.cmd run build
npx.cmd wrangler deploy

Deploy worker.mjs as well as the assets. Updating only HTML will not update the response-header CSP. No Supabase migration or function redeployment required.

The analytics script origin and beacon endpoint are allowed. HTML responses receive a fresh cryptographic CSP nonce that Cloudflare can propagate onto its injected scripts. Arbitrary inline JavaScript remains blocked; unsafe-inline is not added to script-src. Static _headers carries the matching analytics allowlist; dynamic nonces require the Worker deployment. HTML validators are removed so old injected-script nonces are not reused via 304 validation.

Recovery forms have a readonly account email with autocomplete=username; it is filled from the authenticated account and cleared on sign-out.

After deploying, hard-refresh My Vault and recheck Console. If a Cloudflare Transform Rule adds another CSP, that policy must permit the same resources; multiple policies all apply. The source HTML contains no executable inline script. If a different inline script remains blocked, inspect that script before adding an allowance. Do not use unsafe-inline to suppress errors.
